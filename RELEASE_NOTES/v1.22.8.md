# MacCrab v1.22.8

A security point release. The only change from v1.22.7 is to the plugin
file broker; detection, storage, install and update behaviour are the same.

## Security

- **The plugin file broker no longer opens a privacy-protected file reached
  through another spelling of its path.** v1.22.7 closed the repeated-slash
  and `/var` spellings, but a protected store such as the Messages database is
  also reachable through the data volume's own mount point
  (`/System/Volumes/Data/…`) and through a home folder that is itself a link.
  Those spellings contain no symbolic link for the broker's open to refuse and
  did not match a protected path, so a plugin whose declared folder covered one
  could read the live file through MacCrab's Full Disk Access, and the consent
  sheet showed it as ordinary content. The broker now classifies by the path
  the system reports for the file it actually opened, whatever spelling asked
  for it, and folds the data-volume mount point in its path checks.
- **A request component that hides a slash inside a Unicode character cluster
  is now refused,** so a symbolic link a plugin plants in its own scratch
  folder cannot slip a path segment past the no-follow open walk.

Only a sandboxed Tier-B plugin with a broad declared read folder could reach
either path, and the download's checks (signature, notarization, update
signature) are unaffected.

## Known limitations

Unchanged from v1.22.7. Startup can still stop before detection starts, for
example when another process holds the event database open at launch, when the
disk has less than about 1 GB free, or when the event database cannot be opened
or its format upgrade cannot finish. **Check for Updates…** does nothing until
the dashboard has been opened once since MacCrab started (choose **Show
Dashboard** first); scheduled daily checks are not affected. The full list is in
[KNOWN_LIMITS.md](https://github.com/peterhanily/maccrab/blob/main/KNOWN_LIMITS.md).

## Upgrade notes

Scheduled update checks offer this release within about a week; **Check for
Updates…** in the menu-bar menu offers it at once. In v1.22.8 and earlier,
choose **Show Dashboard** first; until the dashboard has opened, Check for
Updates… does nothing. Upgrading from v1.21.5 or earlier still changes the
event database format; see the
[rollback runbook](https://github.com/peterhanily/maccrab/blob/main/docs/ROLLBACK_RUNBOOK.md).

Minimum macOS 13.0.
