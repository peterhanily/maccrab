MacCrab v1.21.5

A performance, detection-quality, and reliability release. The headline is a large reduction in engine CPU on machines with a big event database; alongside it several detections are broadened and hardened, and the storage and self-defense paths are made more resilient.

Performance
- Much lower engine CPU on a large database. When the dashboard held an idle read-only connection to events.db, its write-ahead log could no longer be checkpointed and grew unbounded, which drove the storage size-cap sweep into a continuous, CPU-pinning file rewrite. The engine now detects a reader-pinned WAL and backs off instead of churning, and the dashboard releases its cached connection when idle or backgrounded. Steady-state CPU on a busy host drops from a pinned core to near-idle.
- The event database shrinks back to its size cap, and engine memory use is lower. The full-text search index used for threat hunting could grow far out of proportion to the events it covered and was never fully compacted, leaving the database stuck well above its size cap and inflating engine memory (the index is memory-mapped). The size-cap sweep now fully optimizes and reclaims that index — on a test machine this returned a 500 MB database to under 100 MB — freeing both disk and memory.

Detection
- Credential theft by a compromised app helper is now surfaced. A trusted browser or Electron helper (VS Code, Cursor, Slack, and similar) reading a foreign credential store — ~/.ssh, a keychain, a crypto wallet, or another browser's profile — is reported instead of being suppressed as helper noise. A browser reading its own profile stays quiet, so there is no added false-positive noise.
- Hardened reverse-shell detection. The reverse-shell rule now covers a wide range of representations — /dev/tcp and /dev/udp in any spacing or variable-split form, zsh ztcp, netcat/ncat with flags, mkfifo and mknod backpipes, socket/subprocess Python shells regardless of import order, pty.spawn, PHP, perl, socat, gawk, ruby, and node — without false-positiving on benign command lines.
- Multi-step sequence rules honor a live configuration reload. A sequence rule that is deprecated, moved outside the active rule profile, or removed now stops firing without a daemon restart.
- Sequence and graph rules honor the rule profile like single-event rules do: under the default "stable" profile, curated stable-tier rules run and experimental ones stay disabled (set rule_profile: "all" to run everything); deprecated rules never run under any profile.
- Telemetry-drop-evasion detection. The self-defense monitor flags sustained event loss that could be used to blind the sensor gradually, not only sudden spikes, while ignoring brief benign bursts.

Reliability
- Storage-write resilience. Under transient database contention the event writer retries rather than dropping a batch, and under a write flood it preserves rare, high-value process and network records over routine file-write records.
- Database tamper-detection hardening. At-rest integrity checks also account for a value substituted in place of its ciphertext, surfaced at a confidence level appropriate to the ambiguity so legitimate configurations do not false-alarm.

Onboarding
- The first-run setup checklist verifies Full Disk Access and System Extension approval live, instead of assuming them, and only reports the Mac as protected once those checks pass.
- New installs can choose a workspace density (Basic / Standard / Advanced) during setup; Basic is the default for new users.

Intelligence & forensics
- Package Freshness shows "Not scanned" and "—" until a real registry scan has run, rather than defaulting to "up to date" with zero staleness.
- Exported evidence bundles ship a verifiable outer-archive SHA-256 sidecar (`<archive>.sha256`) for transport-integrity checks.

Fleet telemetry (self-hosted prototype)
- Fleet telemetry is strictly outbound-only, requires HTTPS (plain HTTP only for loopback), and the reference server defaults to a loopback bind with an enforced request-size cap and constant-time key check. Fleet remains off by default and is documented as a prototype, not a production feature.

Under the hood
- Genuine end-to-end fire-tests for every stable kill-chain sequence rule; cleared Swift 6 concurrency warnings; a burst-load benchmark and written rule-promotion criteria for contributors.

Minimum macOS 13.0. Notarized and stapled; updates via Sparkle.
