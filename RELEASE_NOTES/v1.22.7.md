# MacCrab v1.22.7

## Engine reliability

- **A database that startup cannot bring under its size limit no longer stops the engine.** If the event or alert database could not be brought under its storage limit at startup, the engine exited and was relaunched into the same failure about every ten seconds, with no detection. v1.22.6 fixed this for TraceGraph only. The engine now starts anyway: detection and notifications run, the database refuses the writes it cannot fit, maintenance keeps running, and the dashboard's storage banner shows it. This includes an event database still finishing its upgrade from the v1.21.5 format. An event database that is over its limit may store no new events until the limit is raised.

## Security

- **The plugin file broker no longer opens protected files through other spellings of their path.** A plugin could get past the protected-path check with a repeated slash or a `/var` spelling and read a privacy-protected file, such as the Messages database, through MacCrab's Full Disk Access, if its declared folder covered that file. The broker also no longer hangs on a named pipe.
- **The threat model no longer says the Rave catalog signing key is kept offline.** It is kept in a keychain on the maintainer's Mac.
- **The privacy policy now covers AI agents connected over MCP:** what they can read without any permission, what is and is not scrubbed, and that the agent's model provider receives it.

## Detection

- **Ten rules now match the paths Endpoint Security actually reports** (`/private/var/…`, `/private/etc/…`). The high-severity `shadow_hash_access` rule could not fire before.
- **Go build and test binaries no longer trigger the ad-hoc-signed execution rule.**

## Install

- **The disk image opens to a styled install window** with three steps: drag MacCrab to Applications, open it from there, and allow it in System Settings. The app has the pixel-crab icon from maccrab.com.
- **The disk image is smaller** (LZMA) and no longer carries metadata from the build Mac.
- **`install.sh` refuses arguments,** so it can no longer install the wrong version when two MacCrab disk images are mounted.

## Known limitations

Sustained extreme bursts, such as large package installs during other heavy work, can still drop file events, which health telemetry counts. Startup can still stop before detection starts, for example when another process holds the event database open at launch, when the disk has less than about 1 GB free, or when the event database cannot be opened or its format upgrade cannot finish. The full list is in [KNOWN_LIMITS.md](https://github.com/peterhanily/maccrab/blob/main/KNOWN_LIMITS.md).

## Upgrade notes

Scheduled update checks offer this release over about a week; **Check for Updates…** in the menu-bar menu offers it at once. On v1.22.6, choose **Show Dashboard** first; until the dashboard has opened, Check for Updates… does nothing. If your v1.22.6 engine is stuck at startup (the dashboard reports storage not ready), update: this version starts in the size-limit cases above. If the engine is still not ready afterwards, `/Library/Application Support/MacCrab/last_crash.json` names the database and the reason; please report it.

Upgrading from v1.21.5 or earlier still changes the event database format; see the [rollback runbook](https://github.com/peterhanily/maccrab/blob/main/docs/ROLLBACK_RUNBOOK.md).

Minimum macOS 13.0.
