# MacCrab v1.22.2

This patch removes the largest sources of false alarms, corrects collector and
permission status, and keeps protection running when the optional trace store
cannot start.

## Fewer false alarms

- **GitHub, Google Drive and other shared hosting are no longer flagged as
  known-malicious domains.** Threat-intelligence feeds list malware by URL; the
  host of each URL was also treated as a malicious domain, so one bad file on
  raw.githubusercontent.com raised CRITICAL alerts for `api.github.com`, `git`
  and `gh`. Shared platforms are no longer turned into domain indicators, and
  existing entries are removed when the cache loads. URL matching and dedicated
  malicious domains are unchanged.
- **A bulk file operation raises one cross-process chain alert, not one per
  file.** A `find`/`mv` pass over thousands of files, or a coding agent reading
  a fresh checkout, previously raised thousands of identical alerts. Chains are
  now grouped by the programs involved; a chain involving different programs
  still alerts.
- **DGA detection no longer flags ordinary service hostnames** such as Datadog
  intake and Apple edge hosts. Hostname depth alone is no longer treated as a
  sign of generated domains.
- **"Endpointsecurityd Down" no longer fires when macOS idles the service
  out.** macOS launches it on demand and stops it when idle while protection
  continues. Only xprotectd, which macOS keeps running, is monitored this way.
- **Self-check and sensor alerts are calibrated.** A self-check probe that
  arrives late no longer raises a HIGH alert, and a moderate dip in process
  activity with nothing lost no longer reports a degraded sensor.

## Reliability

- **The engine starts when the optional trace store cannot.** If the trace
  database could not open, for example because the disk was nearly full, the
  engine stopped and restarted repeatedly with no protection. It now starts
  without trace recording and reports that state. A trace-store startup failure
  caused by storage capacity is reported as such.

## Accurate status

- **Collector health reflects real activity.** Monitors that report only when
  something changes now record each completed check, so a working monitor shows
  as polling and a stopped one shows as stalled. The ES client monitor is always
  listed. Clipboard monitoring shows as disabled in the system extension, which
  has no access to the user clipboard; paste-and-run detection continues through
  the app.
- **The Permissions tab no longer reports a working engine's Full Disk Access as
  missing.** The engine's own access check now decides that row, the summary
  counts only MacCrab's permissions, and internal service names show readable
  labels such as "iCloud Drive".
- **Diagnostic exports list only MacCrab's permissions,** each marked as
  belonging to the engine or the app.
- **Claude Code appears as `claude`** instead of its version number in alerts
  and process details.

## Also included

- Event writes no longer pause right after upgrading a large store from
  v1.21.5 or earlier.
- The optional S3 and SFTP alert sinks now deliver on a schedule and on
  shutdown, and retry failed uploads.

## Upgrade notes

Upgrading from v1.21.5 or earlier still changes the event database format.
Reinstalling an older app over a migrated database is not a supported rollback;
see the
[rollback runbook](https://github.com/peterhanily/maccrab/blob/main/docs/ROLLBACK_RUNBOOK.md).

Minimum macOS 13.0.
