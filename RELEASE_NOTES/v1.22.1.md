# MacCrab v1.22.1

This patch fixes an upgrade failure in v1.22.0, an engine crash on macOS 14,
and makes startup and protection status easier to see.

## Upgrade reliability

- **Fixes an engine crash on macOS 14 during event processing.** Event-context
  bindings now avoid an older Swift runtime allocation-order failure that could
  repeatedly restart the engine before protection became available.
- **Fixes legacy event-store upgrades blocked by a lowered storage limit.** An
  existing store and its SQLite sidecars could exceed the configured allowance,
  causing the engine to restart repeatedly before monitoring began. Migration
  now has a fixed temporary allowance measured before work starts. Interrupted
  boots reuse that allowance instead of granting more space on each restart.
  The allowance remains bound to the same database across a full Mac restart.
- **The configured limit still governs normal operation.** Startup compacts the
  migrated store, restores the configured cap, and confirms normal write
  readiness before monitoring starts. Physical free-space checks and protected
  history remain enforced. A limit too small for protected retained data can
  still require attention; this fix does not silently raise your saved limit.
- Transient SQLite contention during storage initialization receives bounded
  retries. Capacity and integrity failures remain visible.
- **Preserves the previous allowance for legacy alert evidence.** Background
  cleanup no longer reduces inherited evidence from 50 to 16 rows per alert.
  Age and total-size limits still apply. Previously removed rows cannot be
  restored by this update.

## Dashboard performance

- **The dashboard uses noticeably less CPU while it is open.** Its five-second
  refresh republished unchanged rule-telemetry and fleet-status values, and each
  republish redrew the whole window even when nothing had changed. The engine
  only rewrites those figures every thirty seconds, so most refreshes did no
  useful work. Displayed values update exactly as before.
- **The catalog's animated crab no longer animates at full display rate.** It
  runs at a fixed low rate and stops when the window is inactive or Reduce
  Motion is enabled, matching the Overview crab.

## Clearer protection status

- **Migration shows its progress.** Overview and System Health identify the
  upgrade and show processed and remaining event counts. The interface says
  explicitly that monitoring has not started yet. Startup diagnostics retain
  the migration counts for support.
- **The dashboard reconnects after migration without a manual refresh.**
  Connection recovery continues even while the window is inactive, including
  when its first attempt finds stores that are not ready yet.
- **The menu-bar crab gains an exclamation mark when protection is not
  confirmed.** The warning covers startup, upgrades, unavailable engines, and
  degraded protection, including when the dashboard has never been opened.
- **Reload rules reports a queued request, not a completed reload.** The request
  requires a recent ready heartbeat from the selected engine, and the message
  makes clear that completion has not been confirmed.

## Event processing

Background storage maintenance no longer stalls event writes while another
reader has the events database open. Maintenance now detects that immediately
and defers its remaining cleanup to a later pass, rather than waiting out the
write timeout and then attempting work that cannot succeed. The earlier check
only recognised a held database once its write-ahead log had grown past a size
threshold, so a smaller held log was missed. Normal write timeouts and the
required startup and recovery steps are unchanged.

Credential privacy checks use faster matching for ordinary ASCII event fields.
Existing redaction rules and Unicode handling remain unchanged.

## Upgrade notes

Upgrading from v1.21.5 or earlier still changes the event database format.
Reinstalling an older app over a migrated database is not a supported rollback.
Preserve a backup with the engine stopped before upgrading; see the
[rollback runbook](https://github.com/peterhanily/maccrab/blob/main/docs/ROLLBACK_RUNBOOK.md).
Larger stores can take longer to become ready; there is no fixed startup-time
guarantee.

The new startup and reload messages use English fallbacks in other language
catalogs pending translation.

Minimum macOS 13.0.
