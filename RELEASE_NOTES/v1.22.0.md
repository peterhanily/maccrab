# MacCrab v1.22.0

Everything since v1.21.5. This release makes MacCrab honest about its own state,
fixes the reasons it could go quiet without saying so, and carries a full
remediation pass across the sensor, storage, security and AI surfaces.

## Before you upgrade

v1.22.0 upgrades the on-disk databases and installs a barrier against writes
from older versions. **This is one-way.** Reinstalling v1.21.5 or earlier over a
v1.22.0 database is not supported and can start with empty history. With the
engine stopped, take a copy of `/Library/Application Support/MacCrab/` before
upgrading, and keep it until you are satisfied with this release.

## Sensors

- **Three sensors that were silently producing nothing now work.** The
  system-log collector parsed no output at all, so eighteen subsystems —
  Gatekeeper, XProtect, sudo, securityd, sandboxd, Bluetooth, Wi-Fi and more —
  contributed no events on any install. DNS capture bound to a fixed network
  interface and captured nothing on any Mac whose traffic takes a different one,
  voiding all domain-based threat intelligence.
- **Collector health is honest.** A collector could report itself healthy
  forever regardless of whether it had ever produced an event. A sensor that has
  produced nothing since it started now degrades instead, health distinguishes
  "not started" from "running and quiet", and every collector reports why it is
  in its current state.

## Detection

- **Keychain credential theft is reported again.** Every rule covering
  credential dumping through `/usr/bin/security` was being fully suppressed by
  the noise filter — the technique used by the most common macOS infostealers.
- **Fewer confident false accusations.** The intent scorer asserted certainty on
  ordinary activity, including against Apple's own malware-removal tool, and
  labelled routine package installs as worm propagation.
- **Wider active coverage,** including the privacy-permission and network rule
  sources, which were evaluating nothing.

## AI features

- **AI analysis is off until you turn it on.** It was on by default, so any Mac
  running a local model server on the standard port received AI commentary —
  about a sixth of all alerts — without the user ever visiting Settings. If you
  have already configured a backend, nothing changes.
- The AI backend now records why it is on or off at startup. These messages
  previously went to standard output, which release builds discard, so an
  operator whose configured backend failed to load had no way to find out why.

## Security and privacy

- **Encrypted forensic cases open again.** Case encryption keys were written to
  the keychain with one set of attributes and looked up with another, so no
  encrypted case could ever be reopened.
- **Detection-rule signature verification no longer trusts the working
  directory.** The command-line tool resolved its rule-signing trust root from a
  relative path, so anyone able to write a directory you ran it from could
  become the signing authority. The intended signed key now ships inside the app
  bundle.
- **The agent-trace receiver is loopback-only and the privileged control plane
  is bounded.** Alert-history pruning can no longer be asked to delete
  everything, and the control-plane inbox now has drain and rate limits.

## Stability

- Fixed a crash on the enrichment timeout path that could terminate the engine
  under memory pressure. The engine restarted automatically, so the only visible
  symptom was a silent gap in coverage.
- **The engine no longer crashes on a database recovery.** A cached SQLite
  statement could be reused after storage recovery had closed and reopened the
  database beneath it. On one host this restarted the engine 43 times in 46
  minutes.
- **Multi-step detection can no longer lose its memory limit.** The counter that
  bounds in-flight partial sequence matches was maintained by hand across six
  code paths and could drift below zero, after which the cap never engaged and
  the engine grew without bound.
- Startup recovery limits its retry work, reports storage failures, and skips
  redundant maintenance when the store is already healthy.

## Disk, storage and performance

- **A single idle reader can no longer exhaust the disk.** The causal-graph
  database could grow from 5 MB to 6.7 GB in under ten minutes with one reader
  attached, and the size-cap sweep was measuring that inflated size and deleting
  real evidence to compensate.
- **A single misbehaving detection can no longer fill the disk.** Causal-trace
  recording stops before a free-space floor and coalesces repeated identical
  activity. Every store that can grow now has an admission check before the
  write, not only a cleanup pass after it.
- **Event storage reclaims space it has already freed.** A store could hold
  hundreds of megabytes of reusable free space, count it against its own size
  limit, pause writes, and shed new events while doing so.
- **Expired event storage is reclaimed.** The sweep that removes aged event
  blocks treated two documented-transient conditions as failures and gave up for
  the rest of its pass. On a machine running a few hours, 86% of stored events
  were past their retention deadline and still being read on every query.
- **Alert evidence has its own storage budget,** moved out of the event database
  with an explicit per-family cap, so a burst of evidence can no longer consume
  the space reserved for event history.
- Reading recent events no longer rebuilds the whole event index whenever older
  events expire. On busy machines this made the dashboard expensive to leave
  open.
- Reduced event shedding caused by oversized memory reservations during bursts.
  This does not guarantee lossless capture under every workload or storage
  condition.
- Expensive file analysis runs only when a rule actually asks for it, removing a
  large amount of work the engine previously did and discarded.
- The file-activity capture path recovered buffer space it had reserved for a
  category of events it never carries.

## Alerting

- Fixed the notification channel not starting when MacCrab launches without its
  window open, which is the normal case for a menu-bar app. Affected installs
  posted no alert banners at all.
- A large backlog of pending alerts now drains steadily instead of arriving as
  one burst.
- Alert and evidence writes leave working space for the next write within the
  existing storage limit. When space is tight, recovery can checkpoint completed
  writes, reclaim reusable pages, and remove eligible older alert history before
  retrying. If safe recovery cannot make room, the write failure remains
  visible.

## Prevention

- Network blocking now reports whether it is actually in effect. MacCrab writes
  rules into a packet-filter anchor, but macOS evaluates that anchor only when
  the packet filter is enabled and the anchor is registered in the system
  ruleset. MacCrab configures neither, and `pfctl` reports success regardless —
  so blocks were reported that could not occur. Every affected surface, and the
  documentation, now states this plainly. This corrects the reporting; it does
  not change what was being enforced.

## Evidence

- **Recent events now have one exact, authenticated journal.** Search and
  dashboard rows are a bounded projection of it, and every surface says when
  coverage or retained history is incomplete instead of presenting a partial
  result as proof that nothing happened.
- **Late enrichment is durably tied to the event that produced it.** Reviewed
  matches, hashes and signing data settle as an authenticated revision before
  alert fan-out. Oversized or damaged evidence becomes an explicit gap rather
  than a plausible truncated event.
- `maccrabctl trace export` works again. It was opening the causal-graph store
  without a read key, so no trace bundle could be exported — including from the
  dashboard's Export button, which uses the same command.
- **Replaying an evidence bundle now runs the detection rules.** It previously
  replayed the bundle's own recorded results back at you, which proved the file
  was intact but could not tell you whether the current ruleset still catches
  what it caught.

## Diagnostics

- System Health shows the engine's recent alert write-failure count, and
  protection remains degraded while that count is nonzero, even after storage
  pressure clears. It counts failed write attempts within this engine's recent
  24-hour window, not distinct lost alerts.
- Event storage maintenance now reports its own health. It was measured
  internally and never published, so a sweep that gave up on every pass was
  invisible.
- Maintenance messages are recorded at a level macOS keeps. They were written at
  a level the system does not persist to disk, so they could not be read back
  after the fact.
- Rule-reload confirmations are visible on release builds. The message
  confirming a reload took effect went to standard output and was discarded.
- The privileged-change audit trail is visible in the dashboard under
  System › Health. Previously only an AI agent could read it.

## Command-line and agent access

- AI agents can now read the detection corpus they were already allowed to edit.
  Five read-only tools were added: the rule corpus, an explanation of any single
  alert, vulnerability findings, privacy findings, and the browser-extension
  inventory.
- You can turn off the network-enrichment feeds from the command line without
  administrator rights, and the feed stops immediately rather than at the next
  restart. Turning them back on stays a deliberate action in Settings.

## Settings, interface and robustness

- **Hand-edited storage settings can no longer disable a tier.** Nine retention,
  size and interval settings accepted a zero or negative value unchanged, which
  could make a store prune everything the moment it was written. All settings
  now have a floor, applied identically at startup and on a configuration
  reload.
- Contrast, keyboard and VoiceOver fixes across the severity palette, status
  chips and the trace graph, plus larger hit targets.
- Documentation corrected where it described things that do not exist,
  including a data-deletion command and an at-rest encryption switch.

## Known behavior

- Each startup checks retained event history before confirming readiness. Larger
  stores, upgrades, and recovery work can take longer; there is no universal
  startup-time guarantee. The dashboard requires confirmed readiness before
  showing active protection; System Health provides storage details when
  recovery cannot proceed.

Minimum macOS 13.0.
