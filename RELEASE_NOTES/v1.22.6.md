# MacCrab v1.22.6

This release improves Endpoint Security sensor throughput during build storms,
improves TraceGraph recovery on busy developer Macs, removes two ways
storage could stop the engine at startup, corrects how the plugin store
describes the way plugins run, and makes the app, MCP tools and documentation
describe what a default install actually does.

## Sensor throughput

- **Heartbeat clock fields are sampled together.** Collection latency is
  reported separately, so slow health snapshots do not mix an earlier wall
  timestamp with a later engine uptime.

- **Pending sequence steps avoid repeated bucket copies and accounting
  scans on admission.** Duplicate handling, ordering, pressure limits and
  checkpoint accounting remain in place.
- **Events avoid unnecessary waits when no deferred enrichment is ready.**
  Ready-event delivery, the quiet-period timer and shutdown draining remain
  active. These changes do not establish end-to-end lossless throughput under
  sustained overload.
- **The Endpoint Security callback does less work during a build storm.**
  The ES callback used to decode paths and run the file-open admission policy
  on the kernel's dequeue thread. Those decisions now run on a worker, so the
  callback does field checks only and hands the message off in about two
  microseconds. On the same 100,000-message storm the old inline policy
  decided about 26,000 messages a second; the new callback handles about 1.1
  million. This measures callback hand-off throughput, not end-to-end detection
  throughput: bounded downstream queues can still overflow under sustained
  overload, and the heartbeat reports those losses.
- **Agent text reads can no longer push exec, fork and exit out of the
  priority lane.** Ordinary file opens admitted for AI-tool monitoring now
  ride the file lane. Credential, honeyfile and agent-content reads keep the
  priority lane, in order with their exec, and use reserved worker slots that
  an open flood cannot take.
- **Signal events are dropped at the callback** unless they are fatal signals
  aimed at MacCrab or a known security tool. No detection consumed them, and
  a build storm delivered thousands a second into the priority lane.
- **Repeated writes and reads of one file by one process within two seconds
  are coalesced** into the first. The modified close carries the count, and
  credential, honeyfile, persistence and agent-config paths are never
  coalesced.
- **The detection lanes no longer wait on TraceGraph.** Enriched events go to
  a bounded queue drained by its own task, so a slow or recovering trace store
  cannot stall rule evaluation. Measured hand-off went from 6,300 events a
  second with a slow store to over 700,000.
- **The heartbeat tells loss apart from policy.** Filtered and coalesced
  counts, per-stage lane waits, TraceGraph hand-off loss, and a held
  `es_sensor_degraded` state with its opening time are all reported, and the
  sensor banner in System says when a degraded episode began.

## TraceGraph

- **Repeated runs of the same unsigned binary no longer fill the store.** The
  "Unsigned binary executed from download path" trace was created again for
  every run of a binary from a temporary, download or cache folder. On an
  AI-agent developer Mac that was about 61 traces a minute, enough to fill the
  store in minutes and pause graph evidence for hours. Repeats of the same
  binary within five minutes now share one trace.
- **A full store recovers in minutes.** Recovery now tightens its age cutoff
  when it stops making progress, clears stale graph rows in the same pass, and
  is no longer interrupted by writes it is about to refuse. The one-hour
  protection for recent evidence and all size limits are unchanged.
- **Pauses are explained.** System Health and the MCP trace tools say when
  graph persistence is paused, why, what keeps running, how much space recovery
  still has to free, and when the pause began.

## Startup

- **A TraceGraph store that cannot shrink at startup no longer stops the
  engine.** The engine starts with graph writes paused while detection,
  alerting, Sigma and sequence rules run, instead of exiting and relaunching
  into the same state.
- **Upgrading a large events database no longer times out.** The integrity
  check's time budget now scales with the database size, and the dashboard
  shows the engine as starting while it runs.

## Storage maintenance

- **Opening Settings no longer changes engine storage policy.** Explicit
  edits save only the selected setting and any necessary coupled evidence
  adjustment, preserving inherited and unrelated values. Read/save failures
  leave the existing overrides intact. Status messages distinguish saving and
  requesting a reload from confirmation that the engine applied it.
- **Settings and quiet-period draining have executable lifecycle coverage.**
  Tests exercise the production storage binding and timer callback, including
  failed saves, reopen, late enrichment completion and exactly-once replay.
  These checks do not substitute for installed-app or timer-latency testing.
- **Retention cleanup shares commits across small groups of expired blocks.**
  Each group stays within the existing storage reserve and preserves atomic
  rollups and deletion. Startup and pressure recovery retain the one-block
  path. Retention periods, size caps and checkpoint bounds are unchanged.
- **Streaming journal decoding avoids whole-record buffer copies for each
  input chunk.** Record framing, canonical hashes and decoded values are
  unchanged.

## Plugin catalog

- **The Overview no longer says plugin installs run fully sandboxed.** That
  was wrong for every plugin in the store: MacCrab's own plugins run without a
  sandbox, with MacCrab's access. Only plugins from other publishers run in the
  deny-default sandbox.
- **The install sheet says what a plugin is and how it runs.** It shows the
  plugin's signed name and description. For a MacCrab plugin it says it runs
  with MacCrab's access, including Full Disk Access if you granted it, and that
  MacCrab does not block its network use. It also shows the full publisher key
  and the catalog key fingerprint, each with a Copy button.
- **The catalog shows each plugin's signed name and description,** and each
  store plugin's icon from rave.maccrab.com. Built-in scanners keep their
  symbols in the same icon style.
- **A plugin the catalog does not offer can no longer be installed from a link
  or an Update button.** An entry without a status counts as not offered.

## Detection and command line

- The full supply-chain kill-chain rule now starts on `npm install`, which runs
  as node.
- `maccrabctl why <alert-id>` explains sequence, graph and dashboard-authored
  rules, and the alert inspector suggests it instead of a command that did not
  exist.
- `maccrabctl trace list` shows whole severity labels on a terminal.

## Accuracy

- The plugin store, threat-intel feed sheet, in-app Docs, Welcome screen and
  command-line messages no longer overstate what MacCrab does: first-party
  plugins run with MacCrab's own access, URLhaus and MalwareBazaar need an
  abuse.ch Auth-Key, and nothing is blocked by default.
- README, FAQ, PRIVACY, SECURITY, TRUST and THREAT_MODEL now separate the 486
  shipped rules from the 116 enabled by default, describe plugin sandboxing
  accurately, state that Agent Traces is off by default, and disclose the app's
  clipboard check for ClickFix-style paste-and-run commands.

## Update behaviour

Installs older than v1.22.0 see this update as critical: it is offered
immediately and cannot be skipped. Those versions told users and AI agents to
install Python packages that do not exist, and the engine ran a `forensicate`
binary found on the user's `PATH` as root. v1.22.0 removed both. Installs on
v1.22.0 or later update normally.

## Upgrade notes

Upgrading from v1.21.5 or earlier still changes the event database format.
Reinstalling an older app over a migrated database is not a supported rollback;
see the
[rollback runbook](https://github.com/peterhanily/maccrab/blob/main/docs/ROLLBACK_RUNBOOK.md).

Minimum macOS 13.0.
