# MacCrab v1.22.6

This release improves Endpoint Security sensor throughput during build storms
and the engine's per-event processing cost, closes several ways a program
could evade or quiet detection, improves TraceGraph recovery on busy developer
Macs, removes two ways storage could stop the engine at startup, corrects how
the plugin store describes the way plugins run, and makes the app, MCP tools
and documentation describe what a default install actually does.

## Packaging budget

The explicitly approved installed-app disk-size budget is now 183 MiB, up from
182 MiB; the first signed RC12 measured 182.20 MiB. CPU, memory, write-rate,
detection and free-disk limits are unchanged. This budget adjustment does not
replace exact-candidate runtime or release qualification.

## Sensor throughput

- **OPEN admission avoids unnecessary derived facts and path checks.** The
  optimization retains fail-open handling, protected paths, event identities
  and existing queue limits. This is not a claim that installed build-storm
  event loss has been eliminated; that requires exact-candidate qualification.
- **Directory lookup no longer holds the username-cache lock.** A bounded
  username lane prevents stalled lookups from occupying all heavy-enrichment
  workers, including after a deadline. Unavailable results remain retryable
  instead of being cached permanently; expired event subscriptions stay
  terminal. Successful deferred usernames reach the existing rule/sequence
  replay and one terminal user-behavior observation.
- **Terminal enrichment stays terminal.** Late results cannot replace a
  timed-out component, and duplicate patches during final replay are discarded
  with their buffer accounting released.

- **Heartbeat clock fields are sampled together.** Collection latency is
  reported separately, so slow health snapshots do not mix an earlier wall
  timestamp with a later engine uptime.

- **Pending sequence steps avoid repeated bucket copies and accounting
  scans on admission.** Duplicate handling, ordering, pressure limits and
  checkpoint accounting remain in place.
- **Events avoid unnecessary waits when no deferred enrichment is ready.**
  Ready-event delivery, the quiet-period timer and shutdown draining remain
  active. These changes do not establish end-to-end lossless throughput under
  sustained overload.
- **The Endpoint Security callback does less work during a build storm.**
  The ES callback used to decode paths and run the file-open admission policy
  on the kernel's dequeue thread. Those decisions now run on a worker, so the
  callback does field checks only and hands the message off in about two
  microseconds. On the same 100,000-message storm the old inline policy
  decided about 26,000 messages a second; the new callback handles about 1.1
  million. This measures callback hand-off throughput, not end-to-end detection
  throughput: bounded downstream queues can still overflow under sustained
  overload, and the heartbeat reports those losses.
- **Agent text reads can no longer push exec, fork and exit out of the
  priority lane.** Ordinary file opens admitted for AI-tool monitoring now
  ride the file lane. Credential, honeyfile and agent-content reads keep the
  priority lane, in order with their exec, and use reserved worker slots that
  an open flood cannot take.
- **Signal events are dropped at the callback** unless they are fatal signals
  aimed at MacCrab or a known security tool. No detection consumed them, and
  a build storm delivered thousands a second into the priority lane.
- **Repeated writes and reads of one file by one process within two seconds
  are coalesced** into the first. The modified close carries the count, and
  credential, honeyfile, persistence and agent-config paths are never
  coalesced.
- **The detection lanes no longer wait on TraceGraph.** Enriched events go to
  a bounded queue drained by its own task, so a slow or recovering trace store
  cannot stall rule evaluation. Measured hand-off went from 6,300 events a
  second with a slow store to over 700,000.
- **Events cost about half as much to process.** Substring matching in rules,
  sequences and path checks no longer compares character by character on
  plain ASCII text; disabled rules are no longer walked per event; and most
  events no longer wait on sequence state. Lineage, AI attribution and integrity checks avoid repeated
  copies, scans and hashing. On the hot-path benchmark the per-event cost fell
  by about half with identical verdicts.
- **Blocking work no longer occupies the shared task pool.** Capture reads,
  code-signing checks, hashing, user lookups, periodic scans and response
  scripts run on their own threads, so they cannot stall event lanes.
- **Launchd-started programs and login-item registrations are observed.**
  Mutes on system processes no longer hide their exec events or Background
  Task Management additions. More exec events reach the engine as a result.
- **Persistence writes and execute-permission changes are evaluated ahead of
  file floods.** Writes to launch agents and daemons, shell startup files,
  authorized_keys, sudoers and cron tables, and permission changes that grant
  execution, take the priority lane up to a per-sensor rate, so a flood of
  other file activity cannot push them out before evaluation. Login-item
  additions, kernel extension loads and credential-file reads keep reserved
  sensor capacity during floods.
- **The heartbeat tells loss apart from policy.** Filtered and coalesced
  counts, per-stage lane waits, TraceGraph hand-off loss, and a held
  `es_sensor_degraded` state with its opening time are all reported, and the
  sensor banner in System says when a degraded episode began.

## TraceGraph

- **Repeated runs of the same unsigned binary no longer fill the store.** The
  "Unsigned binary executed from download path" trace was created again for
  every run of a binary from a temporary, download or cache folder. On an
  AI-agent developer Mac that was about 61 traces a minute, enough to fill the
  store in minutes and pause graph evidence for hours. Repeats of the same
  binary within five minutes now share one trace.
- **A full store recovers in minutes.** Recovery now tightens its age cutoff
  when it stops making progress, clears stale graph rows in the same pass, and
  is no longer interrupted by writes it is about to refuse. The one-hour
  protection for recent evidence and all size limits are unchanged.
- **Pauses are explained.** System Health and the MCP trace tools say when
  graph persistence is paused, why, what keeps running, how much space recovery
  still has to free, and when the pause began.

## Startup

- **A TraceGraph store that cannot shrink at startup no longer stops the
  engine.** The engine starts with graph writes paused while detection,
  alerting, Sigma and sequence rules run, instead of exiting and relaunching
  into the same state.
- **Upgrading a large events database no longer times out.** The integrity
  check's time budget now scales with the database size, and the dashboard
  shows the engine as starting while it runs.

## Storage maintenance

- **Storage settings are tested through the engine consumer.** Disposable
  fixtures save the seven controls through their production bindings and
  read them through the daemon's authorized override selection and merge.
  These tests do not assert that an installed engine applied a reload.

- **Opening Settings no longer changes engine storage policy.** Explicit
  edits save only the selected setting and any necessary coupled evidence
  adjustment, preserving inherited and unrelated values. Read/save failures
  leave the existing overrides intact. Status messages distinguish saving and
  requesting a reload from confirmation that the engine applied it.
- **Settings and quiet-period draining have executable lifecycle coverage.**
  Tests exercise the production storage binding and timer callback, including
  failed saves, reopen, late enrichment completion and exactly-once replay.
  These checks do not substitute for installed-app or timer-latency testing.
- **Retention cleanup shares commits across small groups of expired blocks.**
  Each group stays within the existing storage reserve and preserves atomic
  rollups and deletion. Startup and pressure recovery retain the one-block
  path. Retention periods, size caps and checkpoint bounds are unchanged.
- **Streaming journal decoding avoids whole-record buffer copies for each
  input chunk.** Record framing, canonical hashes and decoded values are
  unchanged.

## Plugin catalog

- **The Overview no longer says plugin installs run fully sandboxed.** That
  was wrong for every plugin in the store: MacCrab's own plugins run without a
  sandbox, with MacCrab's access. Only plugins from other publishers run in the
  deny-default sandbox.
- **The install sheet says what a plugin is and how it runs.** It shows the
  plugin's signed name and description. For a MacCrab plugin it says it runs
  with MacCrab's access, including Full Disk Access if you granted it, and that
  MacCrab does not block its network use. It also shows the full publisher key
  and the catalog key fingerprint, each with a Copy button.
- **The catalog shows each plugin's signed name and description,** and each
  store plugin's icon from rave.maccrab.com. Built-in scanners keep their
  symbols in the same icon style.
- **A plugin the catalog does not offer can no longer be installed from a link
  or an Update button.** An entry without a status counts as not offered.

## Detection

- **MacCrab's own processes are recognised by code signature, not by name or
  location.** A program named or placed like a MacCrab binary is evaluated,
  scored and alerted on like any other.
- **A code-signing verdict stays with the file it was computed for.** A file
  replaced or removed during or after a check no longer inherits the previous
  file's verdict, and a binary naming itself com.apple.* no longer vouches for
  the processes it starts until its signature is verified.
- **A first launch is still checked when detection is saturated.** The check
  for a revoked certificate or missing notarization runs in the background
  instead of being skipped.
- **File content stays visible past an ill-formed byte.** One stray byte in a
  hook, plist or package file no longer hides its content from content rules
  and the hidden-text scanner, and a payload behind a second hard link is read
  when the writing user owns it.
- **Process properties count once toward behaviour scores and keep their
  weight.** An unsigned program running from /tmp no longer reaches the alert
  threshold through ordinary activity alone, and still alerts when it later
  writes persistence.
- **AI tools copying the login keychain are reported.** Keychain reads by
  Apple tools that an AI agent runs now reach AI Guard; Apple's ssh reading a
  passphrase from the keychain is not reported. Its exemptions for signing
  tools and MacCrab's own tools now require the genuine binaries.
- **Credential reads by a browser are quieted only for its own profile,** and
  git no longer counts as the owner of private SSH keys.
- **Allowlist entries scoped to a file hash or to this host now apply.** A
  hash entry matches only the hash recorded for the process itself.
- **The critical Full Kill Chain campaign can be produced** when credential
  access, persistence and command-and-control appear in a chain of at least
  four tactics.
- **The SKILL.md poisoning rule can now fire**, on the completed write.
- **Fork events are no longer evaluated as process launches,** and only rules
  with regular expressions are disabled for slow evaluation.

## Reliability

- An event lane no longer stops for good after a transient memory refusal.
- Deferred enrichment of one event is replayed in order, so a slower replay can
  no longer lose matches or leave the event pending.
- Evidence of one event is no longer reported as missing because another
  event's storage was refused, and a retried event is no longer filtered as a
  duplicate of itself.
- A failed storage transaction no longer forces a full rebuild of the event
  index.
- Each privacy-permission change is reported once, a change made in quick
  succession is no longer skipped, and clock changes no longer delay detection.
- Retention cleanup no longer stalls behind a slow reader, continues sooner
  after backpressure and gives way to size-cap maintenance; manual cleanup
  waits for it instead of being skipped.
- Process ancestry stays accurate when a process's exit is not observed, and a
  process that reuses a pid no longer inherits another process's children.

## Dashboard

- **The AI Guard tab no longer re-reads the whole event store every few
  seconds.** Recorded agent sessions refresh once a minute while the tab is
  open.
- **Live Events windows no longer lose rows under load.** When a poll returns
  a full page, the window reloads instead of showing a list with a gap, and a
  filtered window reads its own category from the store.
- **A busy engine no longer resets the dashboard's event reader,** which
  forced every open window to rebuild its index.
- **Notifications catch up on a backlog without skipping alerts,** reading
  forward from where they left off.
- **The Events stream shows Paused while the dashboard is not polling.**

## Privacy and access control

- **Granting an MCP agent capability tier goes through a root-only request
  directory.** Another local user can no longer restore a tier the operator
  revoked. `sudo maccrabctl agent-capabilities` writes there; the dashboard can
  still turn tiers off. The tiers gate the MCP server only, as SECURITY.md now
  states.
- **Command lines are redacted consistently.** The stored command line is
  redacted at least as thoroughly as the stored arguments and covers more
  password-argument forms, while ports, process IDs and paths stay visible for
  hunting. OCSF and OpenTelemetry exports apply the same redaction.

## Rules and command line

- `get_alert_detail` shows the definition of graph, auto-generated and user
  rules, and finds a rule without reading the whole corpus.
- The full supply-chain kill-chain rule now starts on `npm install`, which runs
  as node.
- `maccrabctl why <alert-id>` explains sequence, graph and dashboard-authored
  rules, and the alert inspector suggests it instead of a command that did not
  exist.
- `maccrabctl trace list` shows whole severity labels on a terminal.

## Accuracy

- The plugin store, threat-intel feed sheet, in-app Docs, Welcome screen and
  command-line messages no longer overstate what MacCrab does: first-party
  plugins run with MacCrab's own access, URLhaus and MalwareBazaar need an
  abuse.ch Auth-Key, and nothing is blocked by default.
- README, FAQ, PRIVACY, SECURITY, TRUST and THREAT_MODEL now separate the 486
  shipped rules from the 116 enabled by default, describe plugin sandboxing
  accurately, state that Agent Traces is off by default, and disclose the app's
  clipboard check for ClickFix-style paste-and-run commands.

## Update behaviour

Installs older than v1.22.0 see this update as critical: it is offered
immediately and cannot be skipped. Those versions told users and AI agents to
install Python packages that do not exist, and the engine ran a `forensicate`
binary found on the user's `PATH` as root. v1.22.0 removed both. Installs on
v1.22.0 or later update normally.

## Upgrade notes

Allowlist entries created with `maccrabctl allow --hash` or `--host` take
effect after upgrading; earlier versions stored them without applying them.
Review them with `maccrabctl allow list` and remove any you no longer want with
`maccrabctl allow remove <id>`.

Upgrading from v1.21.5 or earlier still changes the event database format.
Reinstalling an older app over a migrated database is not a supported rollback;
see the
[rollback runbook](https://github.com/peterhanily/maccrab/blob/main/docs/ROLLBACK_RUNBOOK.md).

Minimum macOS 13.0.
