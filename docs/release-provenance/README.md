# Historical resource measurement provenance

`resource-baseline-recorder-v1.py.txt` is the complete recorder used for the accepted v1.21.5 reference measurement. It is retained as data and is never imported or executed. Its SHA-256 is `6871807f08e6477db7525c4f78ae522d3b4296095e2a5560b6a500792ed7f33d`; the accepted raw measurement and decision remain private and unchanged. The public resource policy carries only approved summaries, fixed protocol details and commitments to that evidence. That two-executor policy is kept byte-for-byte as `scripts/fixtures/historical-two-executor-resource-policy.json`.

`resource-baseline-recorder-v2.py.txt` is the recorder that took the four-executor remeasurement accepted on 2026-11-04, the policy in `docs/RELEASE_RESOURCE_BASELINE.json`, kept byte-for-byte as `scripts/fixtures/historical-four-executor-resource-policy.json`. Its SHA-256 is `dd7277e703e77bd02a358705eac9011c6b19c9d3f9a980328b7f66349807dc16`. While the current recorder is byte-identical to it, validation does not call the helper below.

When the current recorder differs, `scripts/resource-baseline-provenance.py` permits one of these accepted measurements, chosen by the exact public policy, only after checking the exact archive, public policy, private accepted-evidence commitment and workload executors. The public-policy call also binds the exact in-memory policy document to the frozen file. The original private validator call remains unchanged and binds its complete document through the private canonical commitment. It compares the byte-identical transitive source dependencies of resource capture and validation, including native process identity, sampling, statistics, shared helpers, constants, class definitions and decorators. Imports, CLI dispatch and original top-level ordering remain fixed. New import-time side effects, interpreter namespace changes and effectful defaults are refused.

The only normalization replaces the exact new compatibility-check call with the exact historical recorder-hash refusal. Unrelated runtime-drain function bodies and inert declarations may change; reference measurement behavior may not. A changed measurement dependency requires new reference evidence or a separately reviewed protocol change. The helper is bound by the release-critical executor inventory, and its controls run in clean CI.

This proof preserves historical measurement provenance. It does not qualify a newer installed candidate or turn the failed GA3 runtime capture into a pass.

The frozen policy's `gui_p95_percent` statistic (`nearest-rank-p95-of-ps-pcpu-snapshots`) describes how the v1.21.5 reference was measured. Since v1.22.1 the candidate runtime gate measures `cputime-interval-delta` (per-interval CPU percentages from cumulative CPU-time deltas between consecutive samples), because `ps pcpu` is a decaying average that read 0.0 across a whole epoch against a true ~3%. The numeric `gui_p95_percent` limit is unchanged and provisional: it must be re-measured with the interval statistic, as a separately reviewed protocol change with new reference evidence, before it is treated as tight.
